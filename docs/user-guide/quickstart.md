# User Guide: Getting Started & Quickstart

`qibocal-report` is a modern, lightweight web application and server designed to serve and explore [Qibocal](https://github.com/qiboteam/qibocal) calibration reports interactively.

---

## ⚡ Installation

Install `qibocal-report` in your Python environment (Python 3.10+):

### Using `pip`

```bash
pip install qibocal-report
```

### Using `uv`

```bash
uv pip install qibocal-report
```

### From Source

```bash
git clone https://github.com/qiboteam/qibocal-report.git
cd qibocal-report
pip install -e .
```

---

## 🚀 Running the Server & Application

The command-line tool `qibocal report` provides three execution modes:

### 1. Standard Server Mode

Start the FastAPI backend server and embedded web application on any directory containing Qibocal calibration folders:

```bash
# Serve reports from current directory
qibocal report server

# Or specify a directory and custom port
qibocal report server ./sample_data --port 8000
```

Open your browser at **`http://localhost:8000`**.

### 2. Standalone Client Mode

If you are running report servers across remote lab computers, measurement rigs, or HPC clusters, launch the standalone client on your local workstation:

```bash
qibocal report client --port 8000
```

The client opens directly to the **Server Management** interface, where you can register and monitor multiple remote servers simultaneously.

### 3. Developer Mode (Live HMR)

For frontend and backend developers wanting live Hot Module Replacement:

```bash
qibocal report dev ./sample_data
```

This starts the FastAPI backend (with auto-reload) and the Vite frontend dev server at `http://localhost:5173`.

## 📁 Calibration Run Directory Layout

`qibocal-report` automatically scans and recognizes directories produced by Qibocal:

```text
sample_data/
├── 10:50:56_[0]_resonator_punchout/
│   ├── meta.json               # Execution metadata (author, platform, dates, protocols)
│   ├── platform/               # Initial hardware configuration snapshot
│   ├── new_platform/           # Calibrated hardware parameters snapshot
│   ├── data/                   # Raw data files generated by protocols
│   │   └── resonator_punchout-0/
│   └── report/                 # Pre-cached JSON figures and HTML tables
└── 21:47:29_[3]_pi-pulse/
    ├── meta.json
    ├── platform/
    ├── new_platform/
    ├── data/
    └── report/
```

- **`meta.json`**: Contains run metadata including title, platform, author, execution duration, git commit hash, and list of executed routines.
- **`report/`**: When present, the server serves cached Plotly JSON figures and HTML tables directly for instantaneous load times.
- **On-Demand Generation**: If `report/` is absent, the backend evaluates the protocol routines on the fly.
