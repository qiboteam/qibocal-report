# Desktop Launcher: Installing Qibocamp

The launcher drives the `qibocamp` command line, of the **`qibocamp`** package — a different thing from Qibocal, the calibration library it builds on. Nothing to install by hand: the first time a server, a notebook session or an invitation needs the command line and none is there, the launcher installs it in the background, in an environment of its own, and carries on with what was asked once it is done. While it works, the status bar at the bottom says so, with a spinner and the way to **Running**, where the output is; the line disappears by itself when the installation ends. The environment lives in `~/.cache/qibocamp/envs/launcher` (or `$XDG_CACHE_HOME/qibocamp/envs/launcher`), next to the ones the notebook sessions make. All this needs is a Python 3.10 or newer on the machine: the launcher looks on the `PATH` and in the usual places — Homebrew, `/usr/local`, the python.org installers, pyenv — and says so, in **Configuration**, when it finds none. The same page offers **Install qibocamp** to do it ahead of time or to try again, and **Update** reinstalls the chosen version with its dependencies brought up to date.

What gets installed, unless another version is chosen, is **the very commit the launcher was built from**, fetched as an archive from the repository — no `git` is needed — so the command line takes exactly the options the launcher passes. The installation follows the build: a launcher newer than what it installed — or whose chosen version changed since — updates it before the first server, notebook or invitation that needs it, as it would install it the first time; should that fail, offline say, the installed one serves until the next session. The same requirement is handed to a server started on another machine, as its `--install`. The server is headless, and the launcher's own dashboard is its client.

The launcher then uses, in order:

1. the environment chosen in the developer options;
2. its own installation;
3. the `QIBOCAMP_EXECUTABLE` environment variable;
4. the `PATH`;
5. the usual places — `~/.local/bin`, pipx environments, `.venv` folders, `/usr/local/bin`, `/opt/homebrew/bin`.

The **developer options**, folded under the installation, hold two things. **Version** picks what goes into the launcher's environment — this build's commit first, then the releases on PyPI and the branches and tags of the repository, fetched when the page opens, or *something else*: any requirement `pip install` accepts, a local checkout included. **Save version** stores the choice in `launcher.json`, and the button above becomes **Switch to …** while the installed version differs from the chosen one. **Another environment** is for a checkout of Qibocamp: **Choose environment…** and **Choose executable…** point the launcher at an environment that already has Qibocamp — a virtual environment folder is enough, the launcher looks inside its `bin` (or `Scripts`) directory — and **Detect again** goes back to its own installation. Both choices live in `launcher.json`, next to the other configuration files. The **About** card at the end of the page names this very build — the release it was made for, by its tag, or else the commit it was built from, never a branch — as a link to its page on GitHub, next to the platform it runs on.
